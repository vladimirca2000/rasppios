# Marco 18 — saída gráfica Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Obter um framebuffer 640×480 RGB565 pelo mailbox e desenhar uma cena bitmap verificável no QEMU e no Raspberry Pi 3B+.

**Architecture:** `src/video.rs` será responsável exclusivamente pela negociação do framebuffer, validação do layout e desenho limitado ao buffer. `src/mmu.rs` fornecerá um mapeamento privilegiado, gravável, não executável para a região retornada quando ela não estiver coberta pelo mapa atual. `main.rs` inicializará o vídeo de forma tolerante a falhas e `console.rs` exporá o comando `tela`.

**Tech Stack:** Rust `no_std`, AArch64, mailbox de propriedades BCM2837/QEMU `raspi3b`, MMU de estágio 1 com páginas de 4 KiB, framebuffer RGB565.

## Global Constraints

- Resolução solicitada: 640×480.
- Formato aceito: profundidade de 16 bits, RGB565, little-endian.
- Cada linha usará o stride retornado pelo firmware; nunca será calculado como `width * 2` sem validação.
- Toda leitura/escrita no framebuffer usará `volatile` e limites validados.
- A região de vídeo será privilegiada, gravável e não executável; EL0 não terá acesso.
- Falha no mailbox, formato incompatível ou endereço inválido imprime `tela: indisponivel` e não derruba o kernel.
- O console UART e o teclado USB permanecem funcionando.
- Depois de código ou decisão técnica: atualizar `agent.md` e `README.md`, executar `make check` e copiar o kernel ao cartão FAT32 montado quando necessário.
- O marco só fecha depois de teste automatizado, janela QEMU e monitor do Pi 3B+.

### Task 1: API do mailbox e mapeamento do framebuffer

**Files:**
- Create: `src/video.rs`
- Modify: `src/mmu.rs`
- Modify: `src/main.rs`
- Modify: `.cursor/skills/rasppios-bcm2837/registradores.md`

**Interfaces:**
- Produces `pub fn init() -> bool`, `pub fn available() -> bool` e `pub fn exercise()`.
- Produces `pub fn map_framebuffer(start: u64, size: usize) -> bool` em `mmu.rs`.
- `main.rs` chama `mmu::enable` antes de `video::init`, para que a validação e o mapeamento ocorram antes do primeiro acesso ao buffer.

- [ ] **Step 1: Definir a mensagem estática do mailbox**

Usar uma estrutura `#[repr(C, align(16))]` com palavras para as tags:

```rust
#[repr(C, align(16))]
struct FramebufferMessage {
    words: [u32; 35],
}
```

A mensagem deve conter, nessa ordem, os tags de physical size `0x00048003`,
virtual size `0x00048004`, depth `0x00048005`, allocate buffer `0x00040001`,
pitch `0x00040008` e terminar em zero. Solicitar 640×480 nos dois tamanhos e
16 bits na profundidade. O tamanho total deve corresponder exatamente ao
número de palavras alocadas; não enviar uma mensagem parcialmente preenchida.

- [ ] **Step 2: Implement a transação e validar a resposta**

Reutilizar os endereços do mailbox já verificados em `physmem.rs`:
`0x3F00_B880`, `0x3F00_B898` e `0x3F00_B8A0`, canal 8, alias de barramento
`0xC000_0000`. Validar antes de guardar o estado:

```rust
depth == 16
width == 640
height == 480
pitch >= width * 2
buffer_bus & 0xF == 0
buffer_size >= pitch * height
```

Converter o endereço devolvido do alias de barramento para o endereço ARM
usável somente depois de confirmar que o alias é conhecido e que
`buffer_start + buffer_size` não estoura `usize`. Se qualquer tag não tiver
resposta com o bit 31, retornar `false`.

- [ ] **Step 3: Adicionar o mapeamento MMU protegido**

Implementar `map_framebuffer` com uma tabela de páginas dedicada. Para cada
página coberta pelo intervalo, criar descriptor normal, `AF`, shareability
interna, gravável, `XN` e `AP` privilegiado. Rejeitar intervalos que:

```text
start < 0x00080000
end > 0x3F000000
end <= start
```

Também rejeitar sobreposição com `USER_CODE_VA..USER_STACK_TOP`; o framebuffer
não pode substituir as páginas de EL0. Fazer `dsb sy; isb` antes do primeiro
acesso. Se não for possível mapear o intervalo inteiro, retornar `false`.

- [ ] **Step 4: Inicializar o vídeo sem afetar o boot**

Adicionar `mod video;` e chamar `video::init()` depois de
`mmu::enable(el)` e antes do `console::run`. `init()` só deve publicar
`available = true` depois de a negociação e o mapeamento passarem. Imprimir:

```text
video: 640x480 rgb565 stride <valor>
```

ou:

```text
video: indisponivel
```

- [ ] **Step 5: Compilar e executar o teste de boot**

Run: `cargo build --release && make check`

Expected: compilação sem warnings novos e `make check` continua terminando
com `ok: QEMU raspi3b iniciou kernel8.img duas vezes e o console respondeu`.

### Task 2: Primitivas RGB565 e fonte bitmap

**Files:**
- Modify: `src/video.rs`

**Interfaces:**
- Consumes the framebuffer state produced by Task 1.
- Produces `clear(color: u16)`, `rect(x: i32, y: i32, width: i32, height: i32, color: u16)` and `text(x: i32, y: i32, text: &str, color: u16, background: u16)`.

- [ ] **Step 1: Implementar conversão de cor**

Definir constantes RGB565 explícitas:

```rust
const BLACK: u16 = 0x0000;
const NAVY: u16 = 0x000F;
const WHITE: u16 = 0xFFFF;
const RED: u16 = 0xF800;
const GREEN: u16 = 0x07E0;
const BLUE: u16 = 0x001F;
```

Escrever um pixel com `write_volatile` em um ponteiro `*mut u16`; o endereço
da linha será `buffer + y * pitch` e o pixel será `+ x * 2`. Não usar
referência Rust sobre memória MMIO/framebuffer nem converter o pitch em
quantidade de pixels.

- [ ] **Step 2: Implementar recorte de retângulos**

Calcular `x0`, `y0`, `x1`, `y1` com inteiros assinados e recortar aos limites
`0..width` e `0..height` antes de converter para `usize`. Retângulo vazio não
deve tocar no buffer. O loop interno deve escrever somente pixels já validados.

- [ ] **Step 3: Adicionar a fonte bitmap**

Usar glifos 5×7 para os caracteres presentes na cena (`A–Z`, `a–z`, dígitos,
espaço, `:`, `-`, `/`, `.`). Para um caractere fora da tabela, desenhar um
quadrado vazio. Cada glifo deve usar sete linhas de cinco bits e ser avançado
por seis pixels. `text` deve tratar `\r` e `\n`, quebrar linha e limitar a
área vertical para não escrever fora da tela.

- [ ] **Step 4: Compilar**

Run: `cargo build --release`

Expected: o alvo `aarch64-unknown-none` compila sem erro de ponteiro, índice ou
formato.

- [ ] **Step 5: Commit**

```bash
git add src/video.rs
git commit -m "feat: desenha primitivas e texto rgb565"
```
