# Marco 19 — interface gráfica inicial Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir um compositor gráfico inicial com três janelas, foco por teclado USB e terminal gráfico, mantendo o shell UART funcional.

**Architecture:** `src/gui.rs` será o estado e o compositor do núcleo 0. Ele reutilizará `video::clear`, `video::rect`, `video::text` e uma nova operação pública de flush, sem escrever diretamente no framebuffer. `console.rs` continuará atendendo a UART, enquanto seu loop também chamará `gui::poll()` para que o teclado USB alimente somente a GUI.

**Tech Stack:** Rust `no_std`, framebuffer RGB565 640×480, fonte bitmap existente, DWC2/HID existente, miniUART e QEMU `raspi3b`.

## Global Constraints

- A GUI coexistirá com UART/USB, sem substituir o shell serial.
- O compositor fará redraw completo da cena a cada atualização.
- A cena será 640×480 em RGB565.
- O primeiro marco não terá mouse, arrastar janelas ou processos gráficos.
- `Tab` alternará o foco entre `status`, `terminal` e `eventos`.
- O terminal aceitará `help`, `clear` e `echo texto`; outras linhas mostrarão `gui: comando desconhecido`.
- O estado do terminal terá limite fixo.
- Todo desenho usará as primitivas limitadas de `video.rs`; nenhum endereço de vídeo será acessado diretamente por `gui.rs`.
- Falha gráfica não poderá impedir o boot nem o shell UART.
- O `.env` nunca será rastreado.

- [ ] **Step 1: Expor o flush existente**

```rust
pub fn flush() -> bool {

```

Manter a validação de disponibilidade, limites, alinhamento de 64 bytes,
`dc cvac` por linha e `dsb sy`. Não duplicar a manutenção de cache em

- [ ] **Step 2: Definir o estado fixo da GUI**

Criar em `src/gui.rs`:

```rust
const WIDTH: i32 = 640;
const HEIGHT: i32 = 480;
const TITLE_H: i32 = 24;
const MAX_LINE: usize = 48;
const MAX_EVENTS: usize = 3;

#[derive(Clone, Copy)]
enum Window {
    Status,
    Terminal,
    Events,
}

struct State {
    ready: bool,
    focus: Window,
    line: [u8; MAX_LINE],
    line_len: usize,
    events: [[u8; MAX_LINE]; MAX_EVENTS],
    event_len: [usize; MAX_EVENTS],
}
```

Use uma instância `static mut` acessada somente pelo núcleo 0. Inicialize o
foco em `Window::Terminal`, linha vazia e eventos vazios. Não use alocação
dinâmica nem strings sem limite.

- [ ] **Step 3: Implementar layout e redraw**

Use uma borda clara na janela focada. Escreva no status `EL1`,

### Task 2: Entrada HID e terminal gráfico

**Files:**
- Modify: `src/usb.rs`
- Modify: `src/gui.rs`
- Modify: `src/console.rs`

**Interfaces:**
- `usb::poll()` continuará retornando `Option<u8>`, agora incluindo `b'\t'`
  para HID usage `0x2b` e `0x7f` para Backspace.
- `gui::poll()` consumirá caracteres USB e devolverá `bool` indicando redraw.
- `console::read_line()` continuará consumindo UART, mas não chamará
  `usb::poll()` quando a GUI estiver pronta.

- [ ] **Step 1: Completar a tradução HID**

Em `usb.rs::ascii`, adicionar:

```rust
0x2b => Some(b'\t'),
```

Preservar Enter (`0x28 -> b'\r'`) e Backspace (`0x2a -> 0x7f`). Não mapear
usages desconhecidos para caracteres imprimíveis.

- [ ] **Step 2: Implementar o foco**

Em `gui::poll()`:

```text
Tab       -> Status -> Terminal -> Events -> Status
Backspace -> remove byte da linha do terminal
Enter     -> executa linha local e zera a entrada
0x20..7e  -> adiciona se houver espaço
outros    -> ignora
```

Cada transição grava um evento limitado e retorna `true`. O foco só muda com
Tab; caracteres em janelas não terminais devem ser registrados como eventos,
sem alterar o terminal.

- [ ] **Step 3: Implementar comandos locais**

Ao receber Enter no terminal:

```text
help       -> "help clear echo"
clear      -> apaga o histórico visível do terminal
echo texto -> mostra "texto"
outro      -> "gui: comando desconhecido"
```

As respostas devem caber no histórico fixo e não chamar `console::reply`, não
ler o cartão e não executar programas EL0. Registrar também o comando na área
`eventos`.

- [ ] **Step 4: Integrar polling sem bloquear a GUI**

No caminho de espera do console:

```rust
loop {
    let gui_changed = gui::poll();
    if gui_changed {
        gui::render();
    }
    if let Some(byte) = uart::try_getc() {
        // fluxo UART existente
    }
}
```

O shell UART deve manter o mesmo eco e os mesmos comandos. O polling USB deve
ser consumido pela GUI quando ela estiver pronta, evitando que uma tecla vá
simultaneamente para o shell serial.

- [ ] **Step 5: Compilar e testar**

Run: `cargo build --release && bash -n scripts/check-qemu.sh`

Expected: sem erros de Rust ou shell; o prompt UART continua retornando após
cada comando.

- [ ] **Step 6: Commit**

```bash
git add src/usb.rs src/gui.rs src/console.rs
git commit -m "feat: adiciona foco e terminal grafico"
```
